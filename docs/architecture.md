# 当前架构与安全边界

## 进程和服务发现

桌面 EXE 持有真实认证、连接与权限状态；同一 EXE 的 `mcp` 参数提供 stdio MCP。MCP 按正在运行的 Remote CLI 桌面进程发现服务，连接带 PID 的当前用户专用管道，用 `GetNamedPipeServerProcessId` 核对实际服务 PID，目录不作为身份条件。

`remotecli_connection_discover` 可选择已发现的服务。会话期间保持绑定，原服务退出后要求重新发现，避免静默更换远端。当前 Windows 用户仍是本地信任边界。控制管道和 broker 管道均按 PID 隔离，并校验版本、请求 ID、类型、大小和超时。

## 认证及长连接

被控端向 Relay 注册用户名授权和独立 owner token；连接密码不进入 Relay API。固定密码采用用户名绑定的 PBKDF2-SHA256，随机密码为 256 bit。HMAC 证明绑定会话、角色、显示身份、随机挑战、临时证书及初始权限，随后固定远端证书并建立 TLS 1.3 通道。被控端拥有权限，主控端不再审批。当前协议不是 PAKE，弱固定密码仍存在离线猜测风险。

邀请到期只约束待连接阶段。传输配对后，Relay 改用 90 秒空闲超时；认证主控端每 20 秒发送 TLS 内 ping，被控端返回 pong，长期无应答会结束连接。客户端移除原来的 24 小时终止定时器。主动关闭、网络故障和帧/流量资源上限仍会结束会话。

VPS 不解密业务帧，但能看到用户名、会话号、连接角色、时间、公开握手信息、认证证明及流量大小。外层 HTTPS/WSS 和内层端到端 TLS 是不同的保护。

## 动态权限

被控端维护递增版本的 `Permissions / WorkspaceRoot / WorkspaceRestricted` 策略，并在本机维护不经协议传输的 `AutoApproveTools` 开关。UI 改动、选择工作区、安装工具或改变自动审批会撤销旧代次操作；可同步的权限、工作区字段通过 TLS 内 `session.policy` 传递。主控端更新状态版本和工具列表，每次 MCP 调用仍重新查询状态并校验 session/stateVersion。

执行与取消合并；查看会话决定会话信息和工具目录读取。全部操作关闭后连接仍可保持并恢复。远端独立检查每个操作的权限、身份、序号与操作 ID。近期 ID 记忆有界，严格递增序号持续防重放，正常长会话不再在第 257 次操作后失效。

文件工具的读、写和已安装工具执行默认由被控端按类别确认；批准只保留到当前策略或会话结束。自动批准只保存在被控端进程内，每次启用都要通过桌面风险确认，不写入配置文件或 MCP 协议。工具队列最多容纳 16 个调用、同时运行两项；审批一次只显示一个请求。请求取消或两分钟执行期限到达时，等待项会退出，活动审批窗口关闭，工具不会在取消后启动。主控端 Codex 通过 `remotecli_remote_tools_list` 发现远端文件工具，再用 `remotecli_remote_workspace_read/remotecli_remote_tool_receive` 调用固定只读白名单；通用 `remotecli_remote_tool_call` 仍用于其他工具且没有只读标注。文件能力不是 MCP resources。只读浏览使用只读文件工具，不使用远程命令。MCP 无扩权或选择被控端工作区的写接口。

## 工作区与命令沙箱

受限文件工具统一规范化路径，拒绝越界、备用数据流、设备路径和重解析点。关闭限制后可以按被控端当前用户权限访问其他本地路径。

受限命令使用 Windows LPAC AppContainer，仅授予 PowerShell 所需的 `registryRead`、`lpacCom`、`lpacInstrumentation` 能力，不授予网络或用户文件目录能力，关闭通用应用包的环境授权。明确列举继承句柄，并使用 kill-on-close Job Object 约束子进程树；每个沙箱最多 16 个进程、单进程提交内存 768 MiB、整个进程树提交内存 1 GiB、CPU 周期硬上限 50%。若系统不支持 CPU 限速，会在命令输出中说明，其他进程和内存限制继续生效。每个 Remote CLI 桌面服务进程同时最多执行两条受限命令，超过时立即返回 `sandbox_capacity`，避免跨会话无限叠加临时快照。隔离配置失败返回错误，不降级运行普通进程。

命令通过 `Workspace:` 驱动器在专用工作区副本执行；命令正文走 stdin，避免 Windows 命令行长度截断。快照文件复制时同时计算 SHA-256，避免为建立源版本清单再读取一次副本。真实工作区 ACL 和完整性标签不修改，只初始化本次新建容器的私有存储。副本最多 512 MiB / 20000 文件并拒绝重解析点。成功后校验源文件 SHA-256 并同步；冲突拒绝覆盖，提交异常或取消使用日志回退，执行失败/超时/撤权丢弃副本。系统运行文件及必要只读注册表访问由 Windows 基础运行权限控制。

关闭工作区限制后，命令使用被控端当前用户的普通进程和文件权限；这个状态不应描述为继续处于工作区沙箱内。

## 工具和数据

内置系统/工作区信息、目录浏览和创建、文件及文本搜索、分页读取、创建/带哈希写入/精确编辑、复制/移动/删除。已安装脚本也使用策略代次和命令运行器，受限时同样在 LPAC 副本执行。参数与结果经过 schema、字段和消息大小检查，工具结果最多 16 KiB，命令保留输出、退出码和最终状态。

MCP 的三种连接状态相互独立。远端失败或断线返回明确错误，不得用主控端本机工具替代。对话存储默认关闭，仅显式启用并经客户端同步后写入程序目录。MCP 提示词不能禁用 AI 客户端提供的其他工具，客户端自身白名单仍负责其余能力的硬隔离。

主控端模型反向调用的本地原型已实现：双方授权并连接成功后，主控端 UI 按 `design/chat-empty.html` 的空对话布局显示本机 Codex 临时对话；被控端也可通过现有会话请求主控端生成回复。两侧上下文分开保存在本次会话内存，断开或撤权即清除。邀请和用户名授权注册发给 Relay 的权限元数据会屏蔽新版可选模型权限，实际权限仍在认证握手中由主控端审批，以兼容尚未升级的 Relay。Codex CLI 自动查找读取桌面配置 `CODEX_CLI_PATH`，其次检查官方默认 Windows 安装目录。原型未部署到 Relay，也未完成真实双端 Codex 登录和 permissions profile 验证；WorkBuddy MCP Apps 路线仍未实现。设计和验证状态见[主控端反向调用评估](controller-model-reverse-call-assessment.md)。
